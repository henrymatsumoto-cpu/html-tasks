O incidente do site em branco

04/09

Vale registrar porque a causa não estava no código do Hub, e a correção mudou como o site serve arquivos para sempre.

Cache do Cloudflare guardou HTML como se fosse JavaScript

  1. Durante o rollout convivem o pod novo e o antigo. O HTML novo pediu um arquivo /assets/index-<hash>.js que só existia no pod novo.
  2. O pod antigo, seguindo o fallback de SPA do Caddy, respondeu index.html para essa URL — com status 200.
  3. O Cloudflare guardou essa resposta por um ano. Todo visitante passou a receber HTML no lugar do JavaScript: tela branca.
  4. Correção: arquivo inexistente em /assets/* agora responde 404 com no-store (o Cloudflare não guarda), arquivo existente vai como immutable e o index.html com no-cache.
  5. Cada build passou a carimbar um __BUILD_ID__ no bundle, então todo deploy gera um hash novo e sai sozinho de qualquer URL envenenada.

Lição que ficou: deploy verde não é site no ar. Depois de cada deploy vale conferir o content-type do bundle.
